# PkuHoleToolkit

> 北大树洞本地备份与关注迁移用户脚本

在北大树洞网页中，把当前账号关注的内容保存为一份本地备份；换号时，也可以只迁移新账号尚未关注的帖子。

**Toolkit 可以独立使用，不需要安装 PkuHoleStudio。** 备份过程只读取数据，不会修改关注、帖子或评论；文件默认保存到浏览器的下载位置。

- 本地备份
- 导出只读
- 关注迁移先检查、后确认
- PkuHoleStudio 联动完全可选

## 安装（约 1 分钟）

1. 安装用户脚本管理器：[Tampermonkey](https://www.tampermonkey.net/)（推荐）或 [Violentmonkey](https://violentmonkey.github.io/)（兼容支持）。
2. 打开 [`PkuHoleToolkit-1.4.1.user.js`](https://github.com/Susurrium/PkuHoleToolkit/releases/download/v1.4.1/PkuHoleToolkit-1.4.1.user.js)，在脚本管理器中确认安装。
3. 登录[北大树洞网页版](https://treehole.pku.edu.cn/web/)，刷新页面。
4. 点击搜索按钮附近的“树洞备份”，即可开始使用。

如果浏览器只是下载了 `.user.js` 文件，请从下载记录中打开它，或在脚本管理器中选择从文件安装。若页面工具栏中没有出现入口，请先确认脚本已启用；脚本会在约 10 秒后于右下角显示备用浮动入口。

当前构建没有自动更新地址。发布新版本后，需要重新从 [Releases](https://github.com/Susurrium/PkuHoleToolkit/releases) 安装；如果脚本管理器中出现两个同名脚本，请只保留最新版本启用。

> 安装时可能会看到访问 `127.0.0.1`、跨域请求和脚本私有存储的权限。这些权限用于可选的 Studio 本机联动，以及保存其连接状态和设备密钥；备份与迁移断点另存于浏览器 IndexedDB。从未主动连接 Studio 时，本地备份和关注迁移不会访问本机端口。

## 第一次备份

第一次使用时，保持默认设置即可生成一份完整备份：

1. 点击“树洞备份”，进入“备份到本机”。
2. 保持“全部关注”，或按需选择收藏分组、指定 PID、帖子发布日期。
3. 点击“生成并下载备份”。
4. 将浏览器下载的 `.treehole.zip` 保存到可信位置。

默认设置为“全部关注 + 包含评论 + 附带可直接阅读的文本”，不自动补全引用内容。每次操作都会生成一份新的快照；如有内容未能读取，界面会明确标记并允许重试未完成项。

如果下载没有自动开始，可在“最近备份”中点击“重新下载”。最近备份和任务断点只会在同一浏览器、同一账号下暂存约 7 天；已经下载到电脑的 ZIP 文件不受这个期限影响。

## 换号迁移关注

迁移只会向当前登录账号新增尚未关注的帖子，不会取消或覆盖已有关注，也不会把备份中的正文、评论重新发布到树洞。

1. 在旧账号中生成并保存备份。
2. 登录要接收关注的新账号。
3. 打开“树洞备份”，切换到“迁移关注”。
4. 选择一个或多个 `.treehole.zip`；也支持旧版 `{ holes, comments }` JSON。
5. 点击“检查备份”，核对“将新增”“已关注并跳过”等数量。
6. 确认无误后，点击带新增数量的确认按钮。

“检查备份”只会读取当前关注列表，不会修改账号。只有最后确认后，Toolkit 才会执行新增关注。多个备份会自动合并去重；作为上下文保存的引用帖子不会被迁移为关注。如果当前关注列表没有读取完整，Toolkit 会禁止继续写入。

## 常见问题

### 使用 Toolkit 必须安装 PkuHoleStudio 吗？

不需要。本机备份、重新下载、断点恢复和关注迁移都可以独立完成。只有已经安装 Studio，并希望把备份直接发送到桌面端时，才需要连接它。

### `.treehole.zip` 里有什么，可以直接查看吗？

ZIP 中包含完整的机器可读归档；默认还包含 `readable.txt`，解压后可以直接阅读。请保留原始 ZIP，不要只保存其中某个文件，否则以后可能无法完整迁移或导入。

### 备份文件保存在哪里？

文件保存在浏览器设置的下载位置。Toolkit 不会替你上传到网盘或第三方服务器。最近生成的备份还可以在“最近备份”中重新下载，无需再次读取树洞。

### “按帖子发布日期”是什么意思？

它按帖子本身的发布时间筛选，不是按你关注它的日期筛选；开始和结束日期都包含当天。

### “补全一层引用内容”是什么意思？

它会把正文或评论中引用的 `#PID` 一并保存，便于保留阅读上下文，因此可能加入所选范围之外的帖子。补全的引用内容不会在迁移时自动变成关注。

### 刷新页面或任务失败后，需要从头开始吗？

通常不需要。暂停、刷新页面或意外中断后，可以在约 7 天内从断点继续；部分失败时可以只重试未完成项。主动取消任务或“放弃断点”后不能继续，关闭工具面板本身则不会停止正在运行的任务。

### 为什么全部关注并包含评论时需要较长时间？

Toolkit 会同时处理最多 6 个帖子，每个帖子的评论按页读取。读取请求在整个当前页面内共享 200–300ms 的启动间隔，最多 6 个请求同时在途；关注列表和评论默认每页请求 200 条，服务端明确拒绝时自动回退到兼容页大小。数据较多时请等待页面中的进度更新，也可以暂停后继续；不要在多个标签页同时启动大批量任务。

遇到 429 时，整个当前页面内的请求会一起等待服务端指定的时间；没有指定时等待 60 秒，然后先用一个读取请求检查是否恢复。单个读取最多尝试 3 次，第三次仍被限流则暂停任务。读取超时为 30 秒。新增关注仍逐个执行，保留 1000–1300ms 的请求启动间隔，不自动重发写入。

### 看不到入口或没有下载文件怎么办？

- 确认脚本已启用、账号已登录，地址是 `https://treehole.pku.edu.cn/web/*`，然后刷新并等待约 10 秒。
- 检查浏览器是否拦截下载；归档已生成时，可从“最近备份”重新下载。
- 遇到 429 时请等待后再继续；遇到 401 或 403 时，请重新登录并刷新页面。

### 如何更新？

当前版本不会自动更新。打开 [GitHub Releases](https://github.com/Susurrium/PkuHoleToolkit/releases)，安装最新 `.user.js` 即可。升级前最好先完成或暂停正在运行的任务。

## 更多功能

- 备份全部关注、某个收藏分组、指定 PID 或帖子发布日期范围。
- 归档始终包含帖子正文；可选包含评论、附带阅读版，并补全正文或评论中的一层 `#PID` 引用。
- 最近备份可以重新下载，也可以按相同设置再次生成。
- 支持暂停后继续、刷新后恢复，以及只重试未完成项。
- 支持一个或多个新版 ZIP，也兼容旧版 `{ holes, comments }` JSON；迁移前自动预检、合并去重并二次确认。
- 单次新增关注请求不会自动重发。用户手动重试时，Toolkit 会先核对当前状态，只对仍未关注的 PID 再次尝试，并检查最终结果。
- 可选把同一份备份发送到已连接的 PkuHoleStudio；发送失败不会影响已经完成的本地备份。

## 可选：连接 PkuHoleStudio

只有已经安装 PkuHoleStudio，并希望把备份直接发送到桌面端时，才需要阅读本节。不了解 Studio 的用户可以完全跳过。

1. 启动 Studio，展开 Toolkit 中的“可选：连接 PkuHoleStudio”。
2. 点击“连接 PkuHoleStudio”。
3. 在 Studio 的“Toolkit 传输”页面核对验证码并确认。
4. 连接成功后，可以发送“最近备份”，也可以选择“备份完成后同时发送到 Studio”。
5. Studio 收到文件后仍会先检查内容，由你确认后才导入。

Toolkit 发送的是与本地下载完全相同的归档。连接和传输只访问本机 `127.0.0.1`，不会向 Studio 发送树洞 Cookie、token 或 UUID。已经发起但尚未确认的连接，会在再次打开工具时继续检查状态；可以随时点击“忘记关联”终止。

连接设置中还保留了旧版 Studio 的一次性接收码入口，具体有效期以 Studio 界面显示为准。

## 安全与隐私

- **备份只读：**只读取当前账号能够访问的帖子和评论，不会新增或取消关注，也不会发帖或评论。
- **迁移需确认：**只向当前账号新增尚未关注的 PID；检查、合并和去重阶段不会执行写入。
- **文件默认留在本机：**归档可能包含敏感正文和评论，请像保管私人文件一样保管，不要随意上传到公共云盘或第三方网站。
- **凭据不写入归档：**树洞 token、Cookie 和原始 UUID 不会写入 ZIP 或 IndexedDB。
- **断点会暂存内容：**为了恢复任务，浏览器 IndexedDB 会暂存任务范围、PID、已抓取的正文和评论。任务断点按 7 天有效期管理，过期后会在 Toolkit 下次清理时删除；选择“放弃断点”会立即删除对应任务数据。账号只以不可逆指纹标识，用来阻止在另一个账号下误恢复任务。
- **Studio 私钥留在脚本管理器：**持续关联使用浏览器生成的 ECDSA P-256 设备密钥；私钥保存在用户脚本管理器的私有存储中，Studio 只保存公钥。每次传输仍使用短时、一次性且绑定文件名、大小和 SHA-256 的签名票据，任一端都可以撤销关联。

报告问题时，请只提供浏览器、脚本管理器、Toolkit 版本和界面错误文案；不要公开洞内容、PID、归档文件、Cookie、token 或 UUID。

## 归档格式与兼容性

Toolkit 生成 `.treehole.zip`，其中包含 `manifest.json`、`data.json` 和可选的 `readable.txt`。当前使用 **PkuHole Archive Contract 2.1.0**：`schemaVersion` 为 `2`，`specVersion` 为 `2.1.0`。

这套协议是 Toolkit 与 Studio 共同遵守的文件边界，以独立的 `PkuHoleArchiveSpec` 为中立真源。本仓库在 [`packages/archive-schema`](./packages/archive-schema) 中固定并内置 2.1.0 Schema 与契约样例；Toolkit 运行时不依赖 Studio 或 Spec 仓库。

Toolkit 产品版本与归档协议版本彼此独立。例如 Toolkit 可以升级到 1.5.0，而归档格式仍保持兼容的 2.1.0。

## 开发与维护

要求 Node.js 24 或兼容版本。项目没有第三方运行时或构建依赖。

```powershell
npm ci
npm run check
```

源码位于 [`apps/userscript/src`](./apps/userscript/src)；根目录 [`PKU-Hole export tool.user.js`](./PKU-Hole%20export%20tool.user.js) 是构建产物，不应手工修改。正式用户应安装 Release 中命名后的附件，而不是从源码目录挑选文件。

历史真实环境记录见 [`BETA_TEST_CHECKLIST.md`](./BETA_TEST_CHECKLIST.md)，该文件对应 v1.3 Beta 的 Edge + Tampermonkey 验收，不代表 v1.4.1 的完整浏览器兼容矩阵。当前代码同时保持对 Violentmonkey 所需 GM 接口的兼容。

GitHub 是源码和版本真源。当前构建刻意不包含 `@downloadURL` 或 `@updateURL`，正式版本通过 GitHub Releases 手动安装和更新。

Toolkit 保持为轻量、可独立使用的用户脚本；后续维护集中在官网 API/DOM 兼容、导出完整性、安全迁移和归档交付。桌面数据库、搜索、标签、笔记和 AI 不属于本仓库。[`方案设计.md`](./方案设计.md) 是已归档的早期方案，不再作为开发路线图。
