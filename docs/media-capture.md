# Toolkit 图片备份

适用版本：`1.6.0`。沿用 Observer 的媒体目标规则和 Archive 2.1 可选媒体扩展；没有修改 Observer 或 Studio。用户操作见 [README](../README.md)，本页说明实现和验证范围。

关注列表与评论接口计数不一致时：列表选取 PID/分组/日期范围，逐帖读取详情，再从详情提取正文、回复数、媒体与引用。开启评论时始终读取评论接口，列表或详情的 `reply=0` 不会跳过评论。详情失败保留列表正文，继续尝试评论和已知媒体，但明确标为部分完成；评论数量小于详情回复数也标为部分完成。服务端 `reply` 不被实际评论数覆盖。

## 抓取范围

- 默认启用 `includeMedia`，可在“更多备份选项”关闭。旧版没有此选项的断点继续作为文本备份恢复。
- 解析帖子、评论的 `media_ids`，接受数组、带引号的列表和常见分隔符，并去重。同一媒体 ID 的多个归属保留独立索引，共享已校验的文件。
- 通过同域 `/chapi/api/v3/media/getImageBinary?id=...` 抓取；帖子为 `image` 且没有媒体 ID 时使用 `?pid=...`。评论仅使用媒体 ID。
- 帖子图片先于评论分页抓取。正文先落盘，图片先逐张落盘；评论返回后再落盘并抓取评论图片。引用帖子使用相同流程。不含评论的备份不会请求评论图片。
- 使用当前登录凭证、原账号指纹和共享并发限速队列，每次实际下载和重试前重新核对账号。拒绝重定向，避免携带凭证跟随媒体地址到其他站点。
- 首版只支持图片：JPEG、PNG、GIF、WebP、BMP、TIFF、AVIF、HEIF。保存原始响应字节，不转换格式，不从正文任意 URL 下载音视频。

## 校验和大小边界

响应头与内容特征共同校验，拒绝 HTML/JSON、空内容、不能识别的图片格式及超限内容。读取流期间累计大小并及时中止；对没有 Content-Encoding 的响应核对 Content-Length。SHA-256 用于文件命名、去重和缓存完整性检查；不是完整的图片解码验证。

并发帖子引用同一媒体 ID 时共享正在进行的下载，并为各个帖子/评论保存独立归属；同一次运行中的失败也共享，恢复或补抓会重新尝试。下载前预留可用容量，其他图片在剩余容量不足时等待在途下载释放预留；成功落盘后按唯一 SHA-256 文件计入预算，避免并发任务分别认为空间仍足够。

单图最多 50 MiB，图片合计最多 180 MiB；整个 ZIP 在拼装最终缓冲区之前核对 200 MiB 上限。图片达到预算后，其余图片记录为缺失，文本和已保存图片仍可导出。如果文本和其他归档数据已使整个包超限，停止生成并提示缩小范围；不会产生当前导入器无法接收的超大包。首版没有自动分包和流式 ZIP 写入。

## 持久化和恢复

IndexedDB 版本 2 增加 `media` 和 `mediaFiles`：前者按任务与归属保存元数据，后者按任务与 SHA-256 保存字节。可用索引和对应文件在同一事务提交，凭证不进入这些存储。任务删除与七天清理同时处理图片数据。

每次恢复会检查已有文件的大小、内容格式和 SHA-256，复用完整文件，只补抓缺失或损坏的图片。正文/评论完成状态与图片完成状态分开，媒体重试不重新抓取完整的评论。暂停在图片之间生效，取消会中止正在读取的响应。登录过期、429 或存储不足保留可恢复断点。

仅本地保存的 `detailComplete` 核验字段用于避免在完成评论检查前标记正文/评论完整。新版断点复用已核验详情；旧断点首次继续补做详情和评论核验，避免沿用旧版零评论误判。旧断点的评论/图片选项保持原值。`detailComplete` 不进入归档。

刷新后恢复最近归档也会校验图片；丢失或损坏的文件改为 `missing`，归档和任务降为部分完成，可通过原任务重试修复。旧版断点保持文本备份行为。

## 归档

保持 `manifest.json`、`data.json` 和可选 `readable.txt` 的原有基线，增加：

```text
media/index.json
media/<SHA-256>.<扩展名>
```

声明 `io.github.susurrium.pkuhole.media` 版本 1，`required: false`。索引包含 `ownerType`、整数 `ownerId`、`remoteId`、`variant: original`、`status`；可用文件另有 `path`、`mimeType`、`size` 和 `sha256`。缺失条目没有伪造的文件路径。`counts.media` 是媒体引用总数，`missingMedia` 是缺失引用数，可能多个引用对应同一物理文件。

选择图片备份且存在缺失时，`complete` 为 false，相关帖子为 `partial`，错误清单带媒体归属。关闭图片备份会记录 `exportOptions.includeMedia: false`。内部断点字段和图片二进制不会被序列化到 `data.json`。

阅读文本只列出本地图片路径和缺失提示；图片位于归档文件夹，文本不内嵌图片。Studio 桥接复用同一份完整归档。

## 验证

自动化回归覆盖接口/凭证、图片识别、响应校验、限速重试、超时取消、多图与评论归属、引用图片、去重、逐图暂停、缺失重试、配额失败、预算、损坏修复、旧断点和任务清理。现有 Archive Contract 与 Studio 黄金包兼容测试继续运行。

隔离浏览器夹具：`tests/fixtures/smoke.html?scenario=media` 和 `?scenario=media-partial`；加 `bundle=1` 验证生成脚本，加 `preserve=1` 保留 IndexedDB 验证刷新恢复。模拟缺失场景可将夹具的 `__toolkitSmoke.mediaFixtureState.fail` 设为 false 后重试。夹具只使用模拟 API，拒绝真实写入。

已在本地 Chromium 验证生成脚本实际下载 ZIP、帖子/评论归属、重复文件去重、缺失统计、缺失重试以及刷新后不发起网络请求的归档恢复。

- 125 项自动化测试通过，包含并发帖子共享在途图片、独立归属、零回复评论、容量等待和释放、预算不足保留文本、取消容量等待，以及排队二进制请求的账号核对。

- 缺失补抓重新枚举关注范围后仅下载缺失图片，没有重复读取完整详情、评论或已保存图片；页面无 JavaScript 错误。
- 本轮未使用真实账号请求官方接口；下面的真实数据记录属于 1.5.0 媒体验收，不能作为并发策略的真实环境结果。
